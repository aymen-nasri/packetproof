PacketProof v1.0.0: a two-site company network written as code, and a pipeline that refuses to
merge a change until a disposable copy of the whole network has proved it, then grades its own
gates against 30 planted faults and 12 attack paths.

This first release covers weeks 1 to 9 of the plan. The optional Kubernetes site (week 10) is not
included.

## Results this release stands on

Every number links to the run that produced it.

- **Gate 3 on the released lab code** ([42877631728](https://github.com/aymen-nasri/packetproof/actions/runs/42877631728),
  commit 86b8f81): of 30 planted faults, the static gate caught 19, the live copy caught 8 more,
  and 3 escaped both. All three escapes are latent: another control or the protocol masked them,
  and no traffic changed. 12 of 12 attack paths from a compromised DMZ host were blocked while
  their legitimate flows passed. The run before it, on 00ba68c, gave identical verdicts, as did
  the three runs on 42970a2 ([scorecard](https://github.com/aymen-nasri/packetproof/blob/v1.0.0/docs/scorecard.md)).
- **The pull-request gate:** median 7.0 minutes over 21 pull-request runs (6.2 to 10.0). Gate 2 now
  runs 123 live tests of routing, firewall, NAT, DNS, TLS, MTU, proxy and monitoring.
- **Prod** ([42883900778](https://github.com/aymen-nasri/packetproof/actions/runs/42883900778)):
  both images and both config bundles verified, and a tampered bundle refused; the new bundle
  applied in place in 0.75 s with 0 of 449 requests failed, 0 TCP connections broken and 0 of 200
  pings across the tunnel lost; no drift before or after; Gate 2 123 of 123 afterwards; and prod
  checked that it runs its SOPS-managed WireGuard keys and CA root.

## What is in this release

| File | What it is |
|---|---|
| `packetproof-config-v1.0.0.tgz` | The config bundle for the tagged commit: every router config, ruleset, DNS zone, proxy and CA setting, and the containerlab topology. Rebuilt by the release workflow, which refused to publish unless it matched main's bundle byte for byte |
| `packetproof-config-v1.0.0.sigstore.json` | Its cosign signature (keyless, in the public Rekor log). The bundle also has a GitHub build provenance attestation, checked with `gh attestation verify` |
| `bundle-source.txt` | The commit, the `bundle.yml` run that built the same bytes on main, and their SHA-256 |
| `images.txt` | The router and node images by digest, after their signatures were verified |
| `packetproof-router-sbom.cdx.json`, `packetproof-node-sbom.cdx.json` | Their CycloneDX SBOMs, copied out of the signed SBOM attestations |
| `SHA256SUMS`, `SHA256SUMS.sigstore.json` | Checksums of all of the above, signed |

To check every file yourself, follow [verify.md](https://github.com/aymen-nasri/packetproof/blob/v1.0.0/docs/verify.md).

## Known limits

- Three faults escape both gates; each is explained in
  [limits.md](https://github.com/aymen-nasri/packetproof/blob/v1.0.0/docs/limits.md), with what
  each gate cannot see.
- FRR runs the `traditional` profile to avoid FRRouting/frr#22939, which is fixed upstream but in no
  release yet.
- Six OpenSSF Scorecard checks stay low for reasons that cannot be fixed honestly yet, such as a
  single maintainer and a repository under 90 days old
  ([threat-model.md](https://github.com/aymen-nasri/packetproof/blob/v1.0.0/docs/threat-model.md)).
- Everything runs in containers on GitHub's runners: it does not reproduce hardware, and the runner
  itself is trusted.
