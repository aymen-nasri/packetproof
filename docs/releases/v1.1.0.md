PacketProof v1.1.0: the release that corrects v1.0.0.

After v1.0.0 was released, its code was reviewed in four independent parts, and every finding was
checked again before anything changed. Four findings change what v1.0.0 could honestly claim. This
release fixes all of them, proves each fix with a run, and says plainly what v1.0.0 got wrong
([review-v1.0.0.md](https://github.com/aymen-nasri/packetproof/blob/v1.1.0/docs/review-v1.0.0.md)).
An optional Kubernetes site is out of scope, as it was for v1.0.0.

## What v1.0.0 claimed that was not true

- **The zone firewall could be walked around.** Every container also sat on containerlab's
  management network, one segment that never crossed a router. A "compromised" DMZ host reached the
  database there, port 5432 open ([run 42896114239](https://github.com/aymen-nasri/packetproof/actions/runs/42896114239), a demonstration that was never merged).
  The attack paths never tried it, because they target only the address plan.
- **The ISP could hijack a zone.** The ISP filter denied private space only at the exact /8, /12 and
  /16, and both site routers had accepted a more specific private route from the ISP (same run).
- **"12 of 12 attack paths blocked" was 9 proved and 3 that proved nothing.** The nmap scans behind
  AP-01, AP-04 and AP-08 timed out on every host and reported no ports at all.
- **"No nftables drift on rtr-a" was never checked.** The drift check's self-test reloaded rtr-a's
  ruleset just before the real comparison.
- A wording error, not a number: v1.0.0 called its prod run a change, but both bundles had the same
  router configs.

## Results this release stands on

The lab code is that of commit [3fb6f3f](https://github.com/aymen-nasri/packetproof/commit/3fb6f3f);
the tagged commit changes only documentation after it.

- **Gate 3, three runs with identical verdicts for every fault and both gates**
  ([42902266017](https://github.com/aymen-nasri/packetproof/actions/runs/42902266017),
  [42902610699](https://github.com/aymen-nasri/packetproof/actions/runs/42902610699),
  [42907526683](https://github.com/aymen-nasri/packetproof/actions/runs/42907526683)): of 30 planted
  faults, the static gate caught 19, the live copy caught 8 more, and 3 escaped both, as in v1.0.0.
  No fault was void. 12 of 12 attack paths were blocked while their legitimate twins passed, and
  this time every probe proved it ran. The amended F05 is now caught by both gates.
- **The pull-request gate:** Gate 2 runs 137 live tests. Over the 5 gate runs with these tests, the
  whole gate took a median of 4.1 minutes (3.9 to 4.4), down from 7.0, mostly because the scans now
  finish instead of waiting out their timeouts.
- **Prod** ([42902885547](https://github.com/aymen-nasri/packetproof/actions/runs/42902885547)):
  both images and both config bundles verified, and a tampered bundle, with rtr-a's forward policy
  flipped to accept, refused for both reasons; the lab reported ready; the apply took 0.95 s with
  0 of 449 requests failed, 0 TCP connections broken and 0 of 200 pings across the tunnel lost; no
  drift before or after, and a planted drift was seen and removed; the SOPS-managed identities all
  matched; Gate 2 137 of 137 afterwards. Both bundles had the same router configs, because an
  in-place apply cannot move hosts off the management network: this proves a hitless, drift-free
  apply on the new design, not a change.

## What is in this release

| File | What it is |
|---|---|
| `packetproof-config-v1.1.0.tgz` | The config bundle for the tagged commit: every router config, ruleset, DNS zone, proxy and CA setting, and the containerlab topology. Rebuilt by the release workflow, which refused to publish unless it matched main's bundle byte for byte |

To check every file yourself, follow [verify.md](https://github.com/aymen-nasri/packetproof/blob/v1.1.0/docs/verify.md)
(cosign 3.0 or newer).

## Known limits

- Three faults escape both gates, and a fourth (F26) passes Gate 2 because the firewall already
  blocks what it opens; each is explained in
  [limits.md](https://github.com/aymen-nasri/packetproof/blob/v1.1.0/docs/limits.md), with what
  each gate cannot see.
- No change between different router configs has been measured on the new design yet; the last
  ones ran on v1.0.0's design ([prod.md](https://github.com/aymen-nasri/packetproof/blob/v1.1.0/docs/prod.md)).
- Gate 3 is bounded by F15, whose job takes 31 minutes of its 45-minute limit, and needs more than
  the 20 runners it may use at once, so two runs started together wait for each other.
- Pull requests need not be up to date with main to merge; the gate run on main after each merge is
  what release and prod require.
- FRR runs the `traditional` profile to avoid FRRouting/frr#22939, which is fixed upstream but in no
  release yet.
- Six OpenSSF Scorecard checks stay low for reasons that cannot be fixed honestly yet, such as a
  single maintainer and a repository under 90 days old
  ([threat-model.md](https://github.com/aymen-nasri/packetproof/blob/v1.1.0/docs/threat-model.md)).
- Everything runs in containers on GitHub's runners: it does not reproduce hardware, and the runner
  itself is trusted.
